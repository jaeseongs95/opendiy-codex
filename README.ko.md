# OpenDIY Codex

[English](README.md) · [한국어](README.ko.md)

요청 취소·프로세스 정리, 대화별 제어와 버퍼 방식 진단 로그를 보강한 **Windows용 Codex CLI·Rust App Server 비공식 수정판**입니다.

[R30 다운로드](https://github.com/jaeseongs95/opendiy-codex/releases/tag/v0.165.0-r30.20261101) · [소스 빌드](docs/source-import.md) · [검증 상태](docs/TESTING.md) · [변경 내역](MODIFICATIONS.md)

## 버전

| 구분 | 공식 기반 | 상태 |
| --- | --- | --- |
| **R30 릴리즈** | 0.165.0 | Windows x86-64 CLI·별도 앱 서버·휴대용 패키지 배포 중 |
| **main의 R31 소스** | 0.166.0 | 통합·회귀 검증 중이며 R31 실행 파일은 아직 배포하지 않음 |

R30을 내려받는 것과 main을 빌드하는 것은 버전이 다릅니다. 정확한 소스는 [SOURCE_BASELINE.json](SOURCE_BASELINE.json), 배포된 실행 파일과 검증 범위는 [릴리즈](https://github.com/jaeseongs95/opendiy-codex/releases)에서 확인할 수 있습니다.

## 추가·개선 기능

- **취소와 정리:** 대기 요청까지 취소를 전달하고, 모델 용량 부족 재시도에 한도를 둡니다. 일부 응답을 받은 요청은 자동 재전송하지 않으며 직접 소유한 하위 프로세스를 정리합니다.
- **대화별 제어:** 컨텍스트 창 크기를 지정하고, 메모리 범위와 교정 기록을 관리합니다. 입력창 위에는 하위 에이전트 상태별 개수를 표시합니다.
- **예약 실행:** CLI가 켜진 동안 일정 간격이나 지정 시각에 요청을 실행합니다. 대상 대화가 작업 중이면 그 회차를 건너뛰어 작업이 누적되지 않게 합니다.
- **화면 이력 부담 완화:** 공식 이력 조회와 커서를 재사용하면서 화면에 보유하는 구간을 제한합니다. 모델이 사용하는 원본 대화와는 분리합니다.
- **선택형 진단:** 입력 처리 경로 밖에서 이벤트를 모아 완결된 파일 단위로 저장합니다. 비동기 내보내기에 실패하면 재시도하고, 게시한 파일에는 덧붙이지 않습니다.
- **언어 선택:** 기본 화면은 영어이며 한국어를 전역 설정으로 저장할 수 있습니다. 명령어나 모델 응답을 자동 번역하는 기능은 아닙니다.

위 기능은 R26~R30에 걸쳐 추가되었습니다. R31은 공식 0.166.0으로 기반을 옮기고, 요청·에이전트 실행 수명, 이력 조회의 연결 사용, 오래된 클라이언트 상태와 예약 명령의 언어 처리를 수정합니다. R31의 최종 빌드·연동 시험·릴리즈 검증은 아직 진행 중입니다.

## Windows에서 실행

1. [R30 릴리즈](https://github.com/jaeseongs95/opendiy-codex/releases/tag/v0.165.0-r30.20261101)에서 `opendiy-codex-r30-windows-x86_64.zip`과 `SHA256SUMS.txt`를 내려받습니다.
2. 압축 파일의 SHA-256을 확인하고, 기존 설치를 보존한 채 새 폴더에 압축을 풉니다.
3. 기존 공유 서버와 분리된 로컬 엔진을 사용하려면 `codex-local.cmd`를 실행합니다. 패키지 상세 사용법은 함께 들어 있는 `USAGE.ko.md`를 참고합니다.

압축 파일에는 CLI·별도 앱 서버·Windows 보조 실행 파일·라이선스·사용법이 포함됩니다. `codex.exe`와 `codex-app-server.exe`도 개별로 받을 수 있지만, 보조 파일이 필요한 기능에는 전체 패키지가 필요합니다. `codex-patched.cmd`와 기본 CLI는 기존 공유 서버에 연결할 수 있으므로 실행한 파일만으로 현재 대화를 처리하는 서버를 판단할 수는 없습니다.

## 주요 명령

PowerShell이 아니라 CLI의 대화 입력창에 입력합니다. 아래 예시는 R30에서 제공하며, R31의 변경은 검증 중입니다.

| 명령 | 용도 |
| --- | --- |
| `/cron add --every 10m -- 빌드 완료 여부를 확인해줘` | 반복 요청 등록 |
| `/cron list` | 현재 대화의 예약 조회 |
| `/cron remove 1` | 1번 예약의 이후 실행 제거. 실제 등록 결과의 번호 사용 |
| `/context 120000` · `/context reset` | 현재 대화의 컨텍스트 창 설정·해제 |
| `/memory view` · `/memory edit <교정 내용>` | 저장된 메모리 조회·후속 통합용 교정 기록 추가 |
| `/subagents` | 하위 에이전트 대화 확인 |
| `/background` 또는 `F6` | 지원되는 터미널 작업을 유지하면서 제어 반환 |
| `/reload_plugin` | 현재 대화의 플러그인 다시 불러오기 요청 |
| `/language ko` · `/language en` | 다음 실행부터 사용할 전역 화면 언어 저장 |

컨텍스트 설정은 다음 턴부터 적용되고 대화를 재개해도 유지되며, 모델 카탈로그의 한도를 늘리지는 못합니다. 메모리 교정 기록은 저장된 요약이나 기존 대화 문맥을 즉시 바꾸지 않습니다. 언어는 저장값보다 `CODEX_UI_LANGUAGE` 환경 변수가 우선합니다.

예약은 CLI를 종료하면 사라집니다. 자연어 예약은 해당 대화에 CLI의 `cron` 도구가 제공될 때 사용할 수 있습니다. 오래된 대화에는 직접 명령을 쓰거나 새 대화를 시작해야 할 수 있습니다. 자세한 내용은 [예약과 하위 에이전트 표시](docs/native-cli-cron.ko.md), [컨텍스트·언어·로그 설정](docs/native-cli-r27.ko.md)을 참고하세요.

## 로그와 검증 범위

로그는 `CODEX_HOME/cli-logging.toml`에서 직접 켜기 전까지 수집하지 않습니다. 항목·버퍼·내보내기 경로를 설정할 수 있습니다. 내보내기 성공은 파일 시스템 게시 성공이며 클라우드 업로드 완료를 뜻하지 않습니다. 이 진단 배치에는 프롬프트 본문과 인증 헤더를 기록하지 않습니다.

[검증 기록](docs/TESTING.md)은 후보별 시험과 남은 확인 사항을 구분합니다. 화면 이력 예산은 프로세스 전체 메모리 상한이 아니며, 구형 대화는 공식 전체 조회 경로를 사용할 수 있습니다. 인증된 모바일 앱의 동일 백엔드 연결과 장시간 부하는 아직 미검증입니다. 프롬프트 캐시 적중률 향상이나 메모리 증가·연결 누적·화면 지연의 완전한 해결을 주장하지 않습니다.

## 두 프로젝트의 역할

| 프로젝트 | 담당 |
| --- | --- |
| **OpenDIY Codex** | CLI·Rust App Server·통신 규약 변경·빌드 도구 |
| [**OpenDIY Desktop**](https://github.com/jaeseongs95/opendiy-desktop) | 데스크톱 화면·다중 세션 관리 |

두 프로젝트는 같은 백엔드를 중심으로 협업합니다. 이 저장소에서 비공개 ChatGPT 데스크톱 자산을 배포하지 않습니다. Git에는 소스와 빌드 도구를, 릴리즈에는 실행 패키지를 올립니다. 인증 정보와 운영 로그는 제외합니다.

### 버전 조합과 검증 상태

| CLI·앱 서버 | OpenDIY Desktop | 확인된 범위 |
| --- | --- | --- |
| 배포 중인 R30 · 공식 0.165.0 기반 | 검증된 조합 미지정 | R30 자체 시험과 Desktop 공동 시험을 구분 |
| R31 후보 · 공식 0.166.0 기반 · `1cd3bbff` | v0.6.0 후보 · `deba0725` | 호환성 관련 규약만 정적 대조. 최종 실행 파일의 공동 시험 대기 |
| R32 재설계 · 구현 초안 `2f42356a` | Desktop 후속 실행 코드 `2fefa895` | [최소 교정 설계](docs/native-cli-r32-design.ko.md). 구현·실제 공동시험 대기 |

같은 행은 함께 확인할 후보이며 호환성 보증이 아닙니다. 실제 공동 시험을 마친 조합만 검증 완료로 표시합니다. 기본 CLI는 기존 공유 서버를 선택할 수 있으므로, 시험할 때 CLI와 실제 서버의 실행 경로·버전·해시를 각각 확인합니다.
