# Codex·ChatGPT Unofficial Patch — Consolidated Release Notes

As of 2026-10-27 · Currently installed in the personal operating environment: **R24 v2**

This document records the history of unofficial, privately maintained patches to the Windows Codex desktop app and its embedded app-server. The desktop executable is named `ChatGPT.exe`, which is why ChatGPT appears in the title. This is **not** an official ChatGPT product release history.

**This is the public version of the change history. The source code published in this repository is at r22; this does not mean that the complete source code for R23, R24, or subsequent candidates, or installable desktop packages, has been published.** No binaries, ASAR archives, proprietary desktop UI assets, personal logs, or authentication data are included. See [Modification Notice](../../MODIFICATIONS.md) for the scope of the published source and [Testing](../TESTING.md) for the scope and limitations of the existing tests.

## Progression of Changes

The work proceeded in this order:

Windows socket-inheritance fix → suppression of repeated access-denied reads → RPC lifetime, cancellation, and request-coalescing corrections → latency and memory diagnostics → Windows MCP pipe and configuration-read fixes → input/RPC correlation and asynchronous logging → plugin reload and per-session Fast settings → automatic recovery from capacity errors, account-switch cancellation, and cache diagnostics.

The table below summarizes preserved records of changes, tests, and deployments from the time they occurred. Dates are in Korea Standard Time (KST). “Previously deployed” means the patch was confirmed running in the personal environment at that time; it does not imply a general release or that every user is running it today. Source revisions such as `r01/r02` and test candidates such as `v2/v3` are not counted as separate desktop app releases.

## Current Features and Usage Notes

- **Access denied:** Denials are not converted into successes. Repeated reads are reduced, while the original permission check runs again on TTL expiry, explicit refresh, or account/access-state changes.
- **Plugin refresh:** R23's `Reload plugins` path is designed to confirm the skills refresh result and the native reconnection-queue response. `queued` is **not** the same as `ready`. Successful reconnection of all services without restarting the app remains unverified.
- **Fast settings:** The current session/draft selection is separate from the global default in General Settings. Guards reject writes from stale handlers after changes in host, account, or manager ownership.
- **Diagnostics:** Input, RPC, DOM/frame, process, retained-collection, and cache measurements are distinct. No samples, failed collection, and disabled instrumentation must not be presented as zero latency or zero memory usage.

The official app base for the currently installed version is **26.1021.3705.0**, with bundled native/app-server **0.164.0-alpha.11.1**, distinct from the separately installed npm CLI **0.164.0**. Runtime confirmation applies to a personal environment launched through a patch-specific launcher. This repository does not distribute a desktop installer or installation instructions.

## Follow-up Candidates — Not Yet Deployed in Operations

### Separate Local Recording from Python Transfer

The app is being changed to first write durable records to local disk and have a separate Python worker transfer them. On the remote drive, each completed record is written to a new file with a 20-digit timestamp inside a date-specific folder; completed files are never appended to. Retry attempts retain the record UUID but receive a new attempt UUID.

Corrections address path aliases that differ only in case, frame/RPC instrumentation correlation, and the collector's metadata interpretation. An additional correction distinguishes legitimate duplicates from real content conflicts when the same logical event is delivered again with a different record UUID.

The initial frozen candidate has isolated-test receipts for **14 commands, all with exit code 0**. For the subsequent fixed package, checks confirmed matching hashes for 8 app overlay files and 24 monitor files, a 41-second worker test, multiple SQLite slices, and event duplicate/conflict differentiation. The independent audit's PASS covers **creation of the fixed candidate, isolated functional verification, and pre-deployment source audit**. Operational files, settings, scheduled tasks, and shortcuts have not been changed.

Actual app startup, user input, long-running load, unmounted remote-drive scenarios, and power-loss conditions remain untested. The local spool has no retention cap and could exhaust available disk space. Passing the candidate tests and audit does **not** mean that the candidate was deployed or that the original problem was fixed.

### Monitor Execution-Time Limits

A candidate removes the 50-second and 40-second forced terminations and consolidates responsibility for submit/latency tasks under one executor. Operational settings remain **a one-minute interval (PT1M), IgnoreNew to prevent overlapping runs, and a five-minute execution limit (PT5M)**. Removal of the operational time limit has not yet been deployed.

### Deferred Work

Per-session context-window UI/native controls, deferring a manual compact requested during an active turn until the next turn, optimization of the most recent 10 turns, and native cache producer r02 were excluded from this expedited release because final validation and builds were incomplete.

## Interpretation of Test Results and Open Questions

There is reproduction and correction evidence for specific socket-inheritance, duplicate-request, pipe-pool-occupancy, duplicate-config-load, and instrumentation selection/truncation defects. Taken together, however, these changes do **not** establish that prolonged typing or chat-switching latency, all connection/process accumulation, memory growth or crashes, and sudden cache-hit declines have been completely resolved. The regressions introduced in R8b/R9 and their subsequent correction/rollback are also retained in the table above.

R17's **NTFS compression** actually reduced allocated storage for historical files. R23's **gzip copy generation** is a separate implementation that preserves the originals, so it is not counted as completed reclamation of the originals' storage. Neither guarantees lossless operation under all failure conditions.

The modified executable has an updated embedded ASAR hash and does not retain the vendor's valid Authenticode signature. The official original was preserved separately. This does **not** mean that signature, authentication, or permission checks were removed.

- R1, R2, R6, R7b, R8b, R9, and R10–R24 are documented to the extent supported by available evidence. R3–R5 are not filled in because independent release evidence was insufficient.
- R7c is a launcher revision for running the r7b app. Independent operational deployment of R12 and R21 is not sufficiently evidenced; candidate tests are distinguished from ports into later versions.
- This document summarizes build, test, and personal deployment records from their original dates. Preparing it did not involve rerunning product tests or exhaustively verifying the current existence and hashes of all historical binaries.
- Personal paths, process identifiers, internal receipts, and operational log locations are omitted from this public edition. For the reproducible r22 test scope in the public repository, see [Testing](../TESTING.md). This document does not publish raw records from private stages.
