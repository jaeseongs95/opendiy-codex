# CLI 예약 실행

예약은 CLI를 켜둔 동안만 유지됩니다. 등록한 대화에서 실행하며, 다른 대화로 이동해도 대상은 바뀌지 않습니다. 실행 시 해당 대화가 작업 중이면 이번 회차를 건너뜁니다. 밀린 회차를 한꺼번에 실행하지 않습니다.

## 직접 등록

아래 명령은 PowerShell이 아니라 Codex의 일반 대화 입력창에 입력합니다.

```text
/cron add --every 10m -- 빌드 완료 여부를 확인하고 실패했으면 근거를 알려줘
/cron list
/cron pause 1
/cron resume 1
/cron remove 1
```

간격은 양의 정수에 `s`, `m`, `h`를 붙입니다. 한 번만 실행하려면 미래 시각과 시간대 차이를 지정합니다.

```text
/cron add --at 2030-01-01T09:00:00+09:00 -- 시험 결과를 확인해줘
```

명령에서 ` -- ` 앞은 일정이고 뒤는 실행할 요청입니다. `1`은 예시이며 실제 등록 결과의 예약 번호를 사용합니다. `remove`는 이후 실행만 제거합니다. 이미 실행 중인 예약 작업을 중단하려면 `/cron cancel 1`을 사용합니다. 취소 요청 수락과 실제 작업 종료는 구분됩니다.

## 자연어로 요청

이 변경을 포함한 실행 파일에서 예약 도구가 제공되는 대화라면 다음과 같이 요청할 수 있습니다.

```text
5분마다 빌드 완료 여부를 확인하도록 cron 걸어줘.
10분마다 빌드 완료 여부를 확인하도록 예약해줘.
이 대화의 예약 목록을 보여줘.
1번 예약을 일시 중지해줘.
```

모델이 CLI의 `cron` 도구를 호출하고 실제 도구 응답을 받은 뒤 등록 결과를 알려줍니다. Windows 작업 스케줄러나 데스크톱 앱의 heartbeat로 대신 등록하지 않습니다. 일정이나 실행할 내용이 부족하면 먼저 확인합니다. 응답이 사라졌거나 처리 시간이 초과됐다면 등록 여부가 불명확하므로 같은 예약을 다시 만들기 전에 목록을 확인합니다. 모델은 호출한 대화의 예약만 조회·변경할 수 있습니다.

기존 MCP 전달 경로를 사용하는 경우 그 경로의 설정·권한 검사를 유지합니다. 내장 app-server에서 MCP 없이 실행하는 경우 새 대화를 시작할 때 예약 전용 도구를 제공합니다. 도구가 없는 오래된 대화에 재개만으로 새 도구를 주입하는 기능은 제공하지 않습니다. 이 경우 새 대화를 사용하거나 `/cron` 명령으로 직접 등록할 수 있습니다. 기존 R28 실행 파일에는 이 자연어 연결 변경이 포함되지 않습니다.

## 하위 에이전트 표시

같은 최상위 대화에 속한 하위 에이전트 상태가 있으면 일반 입력창 바로 위에 상태별 개수 요약이 표시됩니다. 개별 대화는 `/subagents`로 확인합니다. 목록이 비어 있거나 입력창을 대신하는 다른 화면이 열려 있으면 요약 줄이 보이지 않을 수 있습니다. 개별 에이전트 이름을 항상 펼쳐두는 화면은 아닙니다.
